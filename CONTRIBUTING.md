# Contributing

Thanks for considering a contribution to *The Rosetta Developer*.

## Ways to help

- **Fix errors** — technical mistakes, broken code snippets, typos
- **Improve clarity** — if an explanation confused you, it'll confuse others
- **Suggest exercises** — practice problems for existing chapters
- **Translate examples** — additional language pairs are welcome as a future extension

## Ground rules

1. Every code snippet must run as-is. Test before submitting.
2. Follow the format in [`_chapter-template.md`](_chapter-template.md) for new chapters or sections.
3. Keep explanations paradigm-neutral in the "Concept" section — save opinions for "When to Reach for This."
4. One concept per pull request where possible — easier to review.

## Style

- Python: follow PEP 8
- JavaScript: standard ES6+, no semicolon holy wars — match the existing file's style
- Prose: plain language, short sentences, concrete examples over abstract description

## Submitting

1. Fork the repo
2. Create a branch (`git checkout -b fix/chapter-3-typo`)
3. Commit with a clear message
4. Open a pull request describing the change
